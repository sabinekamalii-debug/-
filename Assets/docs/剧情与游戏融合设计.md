# 剧情与游戏融合设计文档

> 本文档不涉及任何具体剧情内容，只定义剧情在游戏系统中如何分布、触发、呈现的结构规则。
> 所有剧情内容均可从零重写，本文档的框架不受影响。

---

## 一、总体架构

### 1.1 大局（Act）结构

- 一局完整的肉鸽对局 = 多个大局
- 每通关一个大局，下一个大局难度提升
- 每个大局固定 **21个关卡节点**，最后一关为Boss关
- 每个大局是一条独立的剧情线，但与其他大局的剧情线互相关联

### 1.2 关卡节点分布（单个大局内）

- 奇遇/商店/休息计入21个节点之中（占据部分节点位，数量有限不会覆盖太多战斗）
- 大致分布：

| 类型 | 说明 |
|------|------|
| 普通关卡 | 从普通关卡池随机抽取，同类随机 |
| 精英关卡 | 从精英关卡池随机抽取，同类随机 |
| Boss关卡 | 固定为本大局的Boss，不随机 |
| 奇遇/商店/休息 | 肉鸽层随机出现，计入21个节点 |

### 1.3 三种模式说明

| 模式 | 普通关卡 | 精英关卡 | Boss关卡 | 说明 |
|------|---------|---------|---------|------|
| 固定模式 | 按序号加载 | 按序号加载 | 固定 | 完全线性体验 |
| 混合模式 | 前N关固定，后续随机 | 随机抽取 | 固定 | 前期稳定后期变化 |
| 随机模式 | 全部随机抽取 | 全部随机抽取 | 固定 | 最大重玩性 |

**关键规则：Boss关永远固定，不参与随机。** Boss是本大局剧情线的收束点，不能打乱。

## 二、剧情分层

### 2.1 两层剧情

| 层级 | 名称 | 作用 | 解锁方式 | 玩家体验 |
|------|------|------|---------|---------|
| 第一层 | 主线骨架 | 推进大局剧情线，保证所有玩家都能看到完整故事 | 绑定进度节点，强制解锁 | 通关就解锁，不可错过 |
| 第二层 | 剧情碎片 | 补完细节，提供多视角和隐藏信息 | 绑定具体条件，可选解锁 | 需要探索/选择才能发现 |

### 2.2 主线骨架的绑定规则

主线碎片默认绑定在**进度节点**上，不绑定具体关卡ID：

```
通关第1关    → 解锁主线碎片（开局引入）
通关第5关    → 解锁主线碎片（剧情推进）
首次通关精英  → 解锁主线碎片（剧情转折）
通关第10关   → 解锁主线碎片（剧情深化）
通关第15关   → 解锁主线碎片（高潮铺垫）
通关Boss关   → 解锁主线碎片（结局收束）
```

**为什么绑进度不绑关卡**：随机模式下第5关可能加载的是LevelConfig #17的地图，但主线碎片讲的是"冒险进行到这个阶段时主角的状态"，与具体战场无关。

**例外**：部分主线碎片可以与特定关卡强绑定。这类碎片即使在随机模式下也一定会在对应关卡触发——随机的只是关卡出现在第几关，碎片跟着关卡走，不会脱节。哪些碎片需要强绑定，后续单独设计。

### 2.3 剧情碎片的解锁条件

碎片通过简单条件解锁，可错过：

- 通关特定关卡 → 解锁该地点的碎片
- 击败特定Boss → 解锁该Boss的碎片
- 招募特定干员 → 解锁该干员碎片
- 奇遇中选择 → 解锁对应分支碎片
- 完成特定奇遇条件链 → 解锁隐藏碎片

### 2.4 碎片命名规则

- 每个碎片有一个**独一无二的名字**（2~6字）
- 解锁时屏幕显示：`✦ 解锁碎片：「碎片名」`
- 名字本身是钩子，暗示内容但不剧透
- 主线碎片的名字串起来构成一条暗线

## 三、奇遇节点设计

### 3.1 奇遇节点的作用

奇遇节点是**玩家做选择的地方**，是自由度的核心来源。主线不分叉，但奇遇里的选择有后果。

### 3.2 奇遇节点类型

| 类型 | 内容 | 玩法 | 剧情作用 |
|------|------|------|---------|
| 无剧情奇遇（多数） | 一句简短描述+三个选项，无Naninovel对话 | 直接选选项拿后果 | 纯玩法，无剧情 |
| 纯剧情奇遇（少数） | Naninovel对话+选择，无战斗 | 看一段过场，做选择 | 揭示世界观/角色信息 |
| 混合奇遇（少数） | 对话→选择→根据选择决定打不打 | 选打有额外奖励，选避开触发另一条线 | 分支碎片解锁 |

### 3.3 选择的后果

**即时后果**（当次Run内立刻生效）：
- 获得金币/卡牌/天赋点/扣血等
- 通过 RandomEventData 的 outcomes 系统实现

**碎片解锁**（跨Run保留）：
- 选择直接解锁某个剧情碎片
- 碎片解锁状态持久化，下一局Run仍保留

### 3.4 奇遇与主线的关系

- 主线不可选——通关就推进，没有分叉
- 奇遇可选——做什么选择是自由的，错过什么碎片是可能的

## 四、大局间的关系

### 4.1 大局独立性

- 每个大局有自己完整的剧情线：引入→推进→高潮→收束
- 单独拿出来可以独立体验，不依赖其他大局
- Boss关是每个大局剧情线的收束点

### 4.2 大局关联性

- 大局之间通过**碎片**互相呼应
- 大局A中某个碎片暗示的内容，在大局B的碎片中有回应
- 大局的Boss之间可能存在剧情关联，但不会直接剧透其他大局

### 4.3 大局解锁顺序

- 第一个大局默认解锁
- 后续大局通过通关前一大局Boss解锁
- 解锁后可以自由选择

## 五、Naninovel脚本结构规则

### 5.1 大局脚本文件

每个大局有一个主脚本文件（如 `plot1.nani`），包含：
- 大局开场（进入大局时播放）
- 各进度节点的主线碎片（通过label跳转）
- 大局结局（击败Boss后播放）

### 5.2 碎片脚本文件

每个碎片有自己的脚本文件或label，通过 StoryCardData.scriptName + labelName 指向。
- 碎片脚本应短小独立（1~3分钟）
- 碎片脚本不依赖大局脚本的上下文，可独立播放

### 5.3 奇遇脚本文件

有Naninovel剧情的奇遇，通过 RandomEventData.naniScriptName 指向脚本。
- 奇遇脚本包含选择分支
- 奇遇脚本可以调用 @loadScene 进入战斗或返回地图

### 5.4 重复播放规则

- 主线碎片：首次通关解锁时自动播放，后续可在剧情碎片收藏中手动重看
- 奇遇剧情：每次遇到都会播放（因为选择可能不同）
- Boss战前剧情：每次遇到都会播放

## 六、与现有系统的对接

### 6.1 StoryCardData 字段映射

| 字段 | 用途 |
|------|------|
| cardId | 碎片唯一ID |
| displayName | 碎片名（2~6字） |
| scriptName | Naninovel脚本 |
| labelName | 脚本内标签 |
| unlockConditionType | 解锁条件类型 |
| unlockParam | 解锁参数 |
| rewardTalentPoint | 首次观看后给予的天赋点数量 |

### 6.2 LevelConfig 字段映射

| 字段 | 用途 |
|------|------|
| levelId | 关卡ID，随机池通过此ID抽取 |
| levelType | 决定随机池分类（普通/精英/Boss） |
| afterLevelLabel | 通关后Naninovel跳转标签 |
| cardToUnlockOnWin | 通关解锁的地点碎片 |

### 6.3 RandomEventData 字段映射

| 字段 | 用途 |
|------|------|
| naniScriptName | 剧情奇遇的Naninovel脚本（无剧情奇遇留空） |
| outcomes | 即时后果（金币/卡牌/血量等） |
| oneShot | 剧情奇遇建议oneShot=true |

## 七、设计约束清单

1. **Boss关不参与随机**——Boss是剧情收束点，必须固定
2. **主线碎片只解锁一次**——重复通关同一进度节点不会重复解锁
3. **奇遇可重复遇到**——但oneShot类型的奇遇只触发一次
4. **碎片可错过**——不是所有碎片都能在一局Run内获得
5. **主线不可错过**——只要通关就一定会解锁对应的主线碎片
6. **碎片名不重复**——全局唯一，作为玩家记忆的锚点
